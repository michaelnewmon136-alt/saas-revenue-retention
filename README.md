# SaaS Revenue Retention: MRR, Churn and Net Revenue Retention

> **All data in this project is synthetic.** It is randomly generated by a script in this repository (fixed seed 42). Nothing here describes a real company, and no result should be read as a finding about real customers or as real savings.

## Business question

A fictional B2B SaaS company is adding new customers, but recurring revenue growth is slowing. Are customers leaving, downgrading, or not expanding fast enough?

## What I built

- **Reproducible synthetic data**: a hidden "truth" table, then seven messy source tables with logged planted problems (duplicates, missing values, inconsistent labels, failed payments, annual billing).
- **dbt + DuckDB pipeline**: 7 staging models, 1 intermediate model, 3 marts (`fct_mrr_movements`, `mart_revenue_retention`, `mart_customer_health`).
- **22 dbt tests**: grain, non-negative MRR, bridge reconciliation, status consistency, missing end dates, and reconciliation between layers.
- **Answer key**: a pandas bridge built from the truth. The dbt bridge matches it exactly in all 35 months.
- **Three-page dashboard**: `dashboard/index.html` (executive revenue, retention, customer health).
- **Recommendation memo**: `memo/recommendation.md`, with a validation plan.
- **Metric contract**: `docs/metric_contract.md` defines every metric before any code.

## MRR bridge

Closing MRR = Opening MRR + New + Expansion + Reactivation - Contraction - Churn

## Key results (simulated data only)

- Gross added MRR rose each year (128K, 186K, 243K) but lost MRR rose faster (29K, 61K, 133K). In 2025 about $55 was lost per $100 added.
- Trailing 12-month NRR is 87.6% and GRR is 65.4% (December 2025).
- SMB cohorts have the weakest 12-month logo retention.
- Usage falls before churn, and escalated tickets coincide with next-month cancellation.
- Enterprise contributes the most contraction dollars.

## Planted patterns (known in advance)

SMB and early-tenure customers churn more, usage declines before about 70% of churns, and escalated tickets precede about 40% of churns. Finding them tests the pipeline. They are not discoveries about a real business.

## How to reproduce

1. Install Python 3.13 and create a virtual environment.
2. `pip install numpy pandas duckdb dbt-duckdb`
3. `python data_generator/generate_data.py`
4. `python data_generator/make_messy_tables.py`, then `make_invoices.py`, `make_usage.py`, `make_support.py`, `make_subscriptions.py`
5. `python data_generator/load_raw_to_duckdb.py`
6. `cd saas_dbt`, then `dbt run --profiles-dir .` and `dbt test --profiles-dir .`
7. `python analysis/answer_key.py` and the `analysis/check_*.py` scripts

## Limitations

- Synthetic data cannot show how real customers behave.
- Correlations do not prove cause and effect. The risk flag is a proposed rule, not a validated prediction.
- Unrecovered failed payments do not cause churn in this simulation, although they often do in real companies.
- Blank MRR is filled from fixed plan prices, which would need checking against billing in a real company.
- Some group sizes (for example Enterprise cohorts) are small, so their rates are noisy.
